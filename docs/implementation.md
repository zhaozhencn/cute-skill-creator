# 实现说明

第一版采用设计文档建议的 Creator Skill 形态。宿主模型承担菜单式集中澄清、业务判断、节点拆解和业务代码编写；标准库 Python 工具承担可重复校验、交付组装、测试执行及证据报告。没有引入网页服务或额外模型供应商依赖。

| 设计要求 | 实现位置 | 可观察行为 |
| --- | --- | --- |
| 菜单式集中澄清与充分性 | SKILL.md；clarification.md；project.json requirements；check | 汇总缺口、一次菜单、统一答复后直接继续；六类需求维度、来源和验收；关键 pending/assumed 阻止生成 |
| 逐节点执行方式 | execution-guide.md；nodes | ai/code/hybrid、依据、依赖、输入输出、约束、失败与人工条件；依赖环和无效引用被拒绝 |
| 混合执行与批准分离 | handoff、validator、scripts；技能指令 | AI 提出候选，代码验证；只对目标实际需要且未授权的操作请求批准 |
| 可执行交付 | build | 生成带 frontmatter 的 SKILL.md，复制实际需要的资源，生成需求和流程说明 |
| 测试覆盖 | tests；validate | 必测层次、正反触发、需求/节点/分支覆盖，AI 至少两次及真实对照 |
| 实际执行 | test；execute | argv 无 shell 执行、stdin JSON、超时回收、stdout/stderr、模型/评审/评分/Token 协议 |
| 修订重测 | revise；内容摘要目录；runs | 留存问题和实际修改；定向重测不复用旧通过，交付最终要求全量 |
| 可追溯报告 | report；manifest；execution-files | 四种状态、输入/预期/实际证据、逐次对照、指标、版本及 SHA-256，未解决项与后续动作 |

## 数据和版本

完整项目契约在 [project-contract.md](../skills/cute-skill-creator/references/project-contract.md)。交付标识由规范序列化的项目、业务源文件、已声明测试资源和 Creator 版本生成。重复 build 可重入；源文件变更生成新目录，历史交付不会被覆盖。

Skill 内容清单校验交付文件；每轮运行保存项目快照、输入与预期、实际脚本副本、执行文件摘要、日志及产物摘要。最近运行指针保存 results.json 摘要，防止通过修改状态误用报告。此机制检查一致性，不提供恶意修改场景下的签名认证。

## 状态与边界

`confirmed/pending/assumed` 是需求状态；`passed/failed/blocked/not_run` 是测试状态，含义不可互换。`check` 就绪也不等于业务已验证。生成时仅做格式、引用和 Python 语法检查；依赖、业务行为和真实模型效果必须通过运行证明。

代码测试采用严格 JSON 断言，区分布尔值与数字。AI 评分来源须为真实执行和评审，运行器检查协议，不能自动证明适配器诚实。对照可以业务得分低但协议必须有效；合法布尔判断错误仍是有效的低质量对照，数字代替布尔不是有效对照。

目录与状态为本地单写入工作流设计；不提供同一工作目录的多进程调度。不同任务应使用独立工作目录。测试命令权限与当前进程一致。

示例订单技能使用整数分计算精确金额，覆盖普通小数、取消订单、空列表、非法输入及超过默认 Decimal 精度的大额累加。其真实模型路由适配器保持未配置，便于观察并验证阻塞状态，而不是凭空给出通过结果。
