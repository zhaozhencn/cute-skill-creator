# 案例：从订单统计需求到可执行技能

本案例说明 `cute-skill-creator` 的一次实际创建和验证过程。业务数据均为明确标注的合成夹具，结果只适用于该次交付版本。

## 用户统一决定业务选项

请求为“创建自动订单分析与洞察报告技能，并完整测试”。创建器复用此前的 Excel/CSV、月度统计和商品／店铺汇总需求，将剩余事项集中为六项菜单。

用户一次回复 `1A，2B，3A，4A，5A，6A`，确定商品明细与退款事件输入、销售按支付月与退款按发生月、中文 HTML＋CSV、经营洞察、本地自动处理，以及异常时停止正式统计。

收到明确答案后，创建、测试、修复与交付连续完成，未在各阶段追加“是否继续”。用户答复前曾再次呈现未答菜单，因此本案例不声称整个对话只有一个助手回合。

## 按步骤分配 AI 和代码

| 步骤 | 执行方式 | 关键约束 |
| --- | --- | --- |
| 读取与校验 | 代码 | CSV/XLSX；重复、缺字段、非法金额及无关联退款停止处理 |
| 指标计算 | 代码 | 整数分计算、按店铺及订单去重、币种隔离、退款发生月归属 |
| 经营洞察 | 混合 | 模型解释指标；代码校验指标摘要和证据引用；独立评审语义 |
| 报告与导出 | 代码 | HTML 与 CSV 使用同一组指标，保留来源和口径说明 |

该次合成样例的 CNY 销售额为 1180.00，退款额为 380.00，期间净额为 800.00；USD 单独统计。期间净额不称为利润，覆盖未核实的月份不计算增长率。

## 实际测试发现问题，再修复

| 实际发现 | 修复及验证 |
| --- | --- |
| 长周期退款产生过多摘要项，合法输入反而失败 | 限制摘要展示数量并披露省略条数，完整指标继续保留；原输入复测通过 |
| 文档限定两位小数币种，脚本尚未落实 | 增加明确支持币种校验，不支持的币种停止处理；原输入复测通过 |
| 来源摘要长文本撑宽手机页面 | 增加换行；390px 视口下页面宽度从 527px 恢复为 390px |
| 损坏 XLSX 只抛底层异常，没有问题清单 | 将工作簿读取异常纳入问题清单；加入回归测试并通过 |

修订后重新执行最终版本的全部 35 项测试：31 项确定性测试，以及 4 项真实模型测试。每项模型测试的候选与无技能对照各执行两次，生成与语义评审分别使用独立会话。最终结果为 **35 通过、0 失败、0 阻塞、0 未执行**。

另一次独立试用直接读取生成的技能和原始 XLSX，连续完成计算、7 条证据洞察及报告渲染，没有额外确认或重试。浏览器检查覆盖桌面、窄屏、证据展开及导出链接。

## 证据与结论边界

[验证快照](examples/order-analysis-validation.json) 保存了运行 ID、交付摘要、各测试的层次与结果、候选和对照执行次数及评分比较。它是本次运行的历史结果摘要，不是可以重新执行真实模型调用的适配器，也不代替完整原始日志。

完整工作目录、模型原始调用和本机安装信息保留在创建时的本地工作区，不作为这个公开案例文档的依赖。仓库提供的可直接复现代码示例是 [order-summary](../examples/order-summary/project.json)；该小示例的两项真实模型触发测试需要另行配置适配器。

本次模型语义测试中，候选与无技能对照均达到验收标准，没有证明总体质量优势。生成与评审采用同一配置模型的独立会话，未做跨模型盲评。合成数据结果不代表生产数据已验证；客户端安装后的隐式技能发现也未通过运行遥测验证。

案例展示的价值是：业务选择能够落成明确的计算规则、可执行文件、实际失败与修复记录，以及与具体版本绑定的验收结果。
